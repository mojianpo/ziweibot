# 产品重设计提案：从"命盘工具"到"问事引擎"

> 背景：iter-25 之后的用户反馈汇总 —— 信息暴露太多、排盘不美观不像专业术数盘、暗色系不对、一屏无法操作、AI 追问不在页内、没有大限/流年/分阶段、缺"算一件事"的板块、可玩性差。
> 本文件是调研（文墨天机/测测/准了/问真八字/Co-Star/The Pattern/Sanctuary/ziwei-chat/iztro 等 18 组检索）+ 代码摸底（引擎能力、AI 通路、主题结构）的综合结论，作为 iter-26 起的重设计基准。

---

## 0. 诊断：问题不在皮肤，在对象模型

现在的产品是 **"一张命盘 + 一份 13 维通读全文"**。这个模型一次倒出所有信息，于是：

| 用户感受 | 对象模型的病根 |
|---|---|
| 暴露太多信息 | 解读不分层，全集平铺 |
| 一屏无法操作 | 盘是"一堵墙"，不是入口；控件挤在边缘 |
| AI 没法针对性追问 | 追问是独立页签，维度上下文靠关键词猜 |
| 看完一遍不再回来 | 只有"本命"一个时间层，没有年度/阶段的回访理由 |
| 没有"算一件事" | 产品以"盘"为中心组织，而不是以"问题"为中心 |

**重做的对象模型：人 × 时间 × 事。**

- **人**：档案（星册已有基础）。
- **时间**：本命 → 大限（十年）→ 流年（年）→ 流月。每个时间层是盘上叠加的一层，不是另一本书。
- **事**：感情/事业/财/学业/健康/自定义 —— 用户带着问题来，产品以问题组织输出。

## 1. 信息架构：三层渐进披露（学文墨天机 / 问真八字）

文墨天机被推崇的原因是"简约而不简单"：基本信息 → 基本命盘 → 专业细盘三层，90% 用户停在第一层。问真八字同屏三栏但靠分层"避免信息过载"。元亨利贞的教训是信息全但无分层。

落地到本应用：

1. **摘要层**（默认）：一句话命局定性 + 四化汇总 + 当前大限/今年流年入口。第一眼不看到任何一颗星。
2. **宫位层**：点哪宫看哪宫。宫格默认只显宫名/干支/主星/四化；辅星煞星庙旺以小字号折叠，点宫展开。
3. **专业层**：四柱、五行局、命主身主、借宫等收纳进中宫"专业"抽屉，需要才打开。

---

## 2. 排盘美学：方形格盘 + 中宫控制区 + 明亮国风

调研确认的行业共识与本应用现状对照：

- **方形 12 宫是主流**（便于录入阅读），本应用已是 4×4 grid，骨架正确，保留。
- **中宫 = 信息与控制区**（华易网/文墨天机/react-iztro 一致）：命主信息、五行局、**时间层切换器（本命/大限/流年）、解读/追问入口**都放中宫。现在中宫是"虚空化"的，改成控制中枢 —— 这直接解决"一屏无法操作"：盘负责看，中宫负责操作。
- **叠加视图而非整盘重排**：流年/大限以角标 + 高亮叠加在本命盘上（流年命宫描边、流年四化加标记），三层同读（流年 > 大限 > 本命）。新 App 已把"流年流月动态叠加 + 一键切换"做成标配。
- **四化颜色语义全文统一**（两套行业约定并存，选一套自洽即可，建议绿禄/紫权/蓝科/红忌 —— 文墨天机约定，化忌红与朱砂同源）。

**明亮色系方向（用户明确要求，调研佐证）**：中文头部玄学产品偏浅色纸感，西方才偏 dark sci-fi。配方（有设计文献支撑）：

- 底：宣纸米白/暖灰（不纯黑也不纯白）
- 正文：炭黑，宋体/楷体标题层级 + 竖排点缀
- 点睛：朱砂红（只做四化/印章级点睛，色不压形）
- 辅色：靛蓝/黛青（宫位层级）、鎏金细线（分割线、高光）
- 大量留白 —— 留白即"呼吸感"，也是高级感的主要来源

Token 层：`tailwind.config.ts` 的 paper/surface/line/ink/zhu/hua/star 全套换值，semantic 名称保留，动效 token 不动。

## 3. 时间轴：大限接数据，流年补引擎（全部真实计算，不编）

代码摸底结论：

- **大限已算**：每宫大限年龄段 + 当前大限标记已有（`algorithm.ts:554-631`，UI 只显示了个年龄角标）。缺大限宫干/大限四化 —— 需按规则补（大限以所落宫起限，宫干即该宫天干，四化由宫干推，引擎的 sihua 工具可直接用）。
- **流年未算**：`generateChart()` 只出本命盘。但 `sihua.ts:71-82` 已有 `getLiuNianSiHua(year)`，缺的是"流年命宫起法 + 流年干支入宫 + 四化落宫"这一层运限盘结构。要新建运限层数据结构（运限十二宫映射到本命十二宫），不是改本命逻辑。
- 流月/流日：helper 也在但未导出，二期再说。

UI：中宫时间轴切换器（本命 → 各宫大限 → 流年选年 → 流月），盘上叠加高亮。**"今年运势"产品化成一页卡片**（年度报告是已验证的刷屏形态：网易云/支付宝年账单范式）。

## 4. 页内追问：差异化机会（商业产品里是空白）

调研确认：商业 App 全是"独立聊天"，只有开源 ziwei-chat 实现了"点击某宫才生成该宫解读 + 就地连续追问 + 证据面板"。我们做进卡片就是领先。

代码现状：追问已带 chartSummary + 最近 6 轮上文（`prompt.ts`），缺的只是**当前宫位/维度注入**。

改动：

1. 每个宫位展开卡片、每条解读维度底部加"就此追问"按钮 → 带上 palace/dimension 参数。
2. `prompt.ts` 收到该参数时，无条件把对应宫位事实 + 对应维原文置顶注入（不再靠关键词猜）。
3. 回答渲染在卡片下原地展开，附引用来源（现有 `cited[]` 字段已支持），形成证据感。
4. AskPanel 独立页签保留为"自由问"，但不再是追问的唯一入口。

## 5. 交互范式：极简对话为主壳（frankfika 形态）

参照 frankfika.com（"和我的 AI 分身聊聊"）：一个输入框、一条对话流，分身的全部人格来自背后的语料。映射到本产品：

- **分身 = 你的命盘**。语料 = 命盘事实 + 13 维原文 + 大限/流年时间层。对话天然"随身携带"：打开就是上次那条线程，盘跟着人走。
- **首页 = 对话**。没有表单墙、没有 13 维页签。一个输入框 + 一条线程 + 意图芯片（今年如何 / 这十年 / 感情 / 事业 / 财运……），芯片就是向导：点"感情"等于选了事类，再问一句"今年呢"等于选了时间范围——第 5 节原来的向导式问事台被对话 + 芯片吸收，不再单独成页。
- **盘不消失，随叫随到**。对话里提到盘面时，命盘以**对话内卡片**形式渲染（可展开、可叠加流年层），而不是跳走离开对话。专业排盘视图退为对话可召唤的"档案视图"。
- **回答必须长结构化卡**：断语 + 依据（引用数据集原文）+ 就地追问输入框，证据感是差异化（防"赛博算命"泛化）。
- 档案（星册）管理收进抽屉；录入新人是对话里的一句话或一个轻表单。

对话线程已有基础（AskPanel + askThreads，按 chartKey 分线程、localStorage 持久化），主壳改造是把首页从 BirthForm 换成对话，意图芯片走 dimension/palace/time 三参数注入（与第 4 节的页内追问共用同一条上下文注入通路）。

## 5+. 问事的原料映射（对话内部机制）

调研确认"选事项 → 选人 → 选时间范围 → 出断语"的结构化 flow **没有任何产品做成标准交互**——我们用"芯片 + 对话"实现它，原料映射不变：

- **事类 → 宫位**：感情=夫妻+福德，事业=官禄+迁移，财=财帛+田宅，学业=官禄+父母，健康=疾厄+命宫。芯片点选即把对应宫位事实 + 维度原文注入上下文。
- **时间 → 运限层**："今年"= 流年叠加，"这十年"= 当前大限，"某年"= 该年流年盘。注入的是引擎真实计算结果。
- **回答形态**：针对问题的断语 + 引用原文 + 就地追问，不是 13 维全文。
- 未覆盖数据集时照常走 not-covered，不补写不编造。

## 6. 可玩性路线图（按验证强度排序，分阶段做）

已验证的留存杠杆（Co-Star/测测/准了/支付宝网易云佐证）：

1. **流年卡"今年运势"** —— 本期随时间轴一起做（第 3 节）。
2. **阶段报告**："这十年（大限）如何"一页卡 —— 本期。
3. 合盘/双人对比 —— 拉新最强钩子，下下期。
4. 克制频率的日签/推送 —— 有品牌反噬教训（Co-Star 频率失控被用户喊删），慎做。
5. 社区/真人咨询 —— 不做（与本产品定位不符）。

宏观威胁注意：通用 AI 赛博算命在吞垂类时长，差异化必须落在"确定性命盘事实 + 可追溯引用 + 专属排盘可视化"上 —— 恰好是页内追问 + 证据面板路线。
